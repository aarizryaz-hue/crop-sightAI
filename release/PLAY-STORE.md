# CropSight Android release

Status: the installable web app and build commands are prepared. **No APK/AAB has been built or uploaded, and no Play listing has been published.** A public HTTPS origin and the publisher's Play Console details have not been supplied yet.

## Ready in the project

- Web app manifest, 192/512px icons, maskable icon and standalone display.
- Offline interface shell; analysis still requires internet. No API/photo/result caching.
- Settings installation control plus browser-menu instructions.
- `/privacy`, with publisher/contact values supplied by environment variables.
- In-app reporting for incorrect, unsafe or offensive AI output, with separate consent. Only result text/comment are submitted; photos are not attached.
- Private report storage with 30-day retention and hourly cleanup.
- Bubblewrap 1.27.0 pinned as a **development tool**. Its generated project targets Android API 36. No npm runtime dependency is needed by the Node server.
- Preflight commands validate the deployed app, privacy configuration, report-storage configuration and Digital Asset Links.

## Needed from the publisher

1. The final public HTTPS origin (no localhost or temporary tunnel). Hosting remains necessary for API calls and for the Android wrapper.
2. A Play Console developer account and its eligibility/verification status. Do not send passwords or identity documents in chat.
3. The real developer/publisher name and public support/privacy email.
4. A permanent Android application ID; choose it during initialization. It cannot be renamed after publication.
5. Private persistent report storage and a way for the publisher to review reports. `REPORTS_DIR` must point to persistent storage, not an ephemeral deployment folder. Use the report ID for deletion requests; delete the matching JSON file. Do not commit or expose report files.
6. Review of the store listing, Data safety answers, age/content rating and final release.

Google's current phone-app target is API 36. New personal developer accounts created after November 13, 2023 generally need at least 12 testers opted into a closed test continuously for 14 days, then production-access approval. An internal test or direct PWA installation can be used earlier where the account is eligible. Google controls review and eligibility; this repository cannot bypass them.

## 1. Host the complete application

Deploy the project including `server.js`, `analysis.js`, `webapp.js`, `index.html`, `references/` and `public/`. Previous three-file upload instructions are no longer sufficient.

For a Node web service:

- Build: `npm ci --omit=dev` (no Android build tools on the server).
- Start: `node server.js`.
- Environment: `HOST=0.0.0.0`, `OPENAI_API_KEY`, optional `OPENAI_MODEL`.
- Set `APP_DEVELOPER_NAME` and `APP_CONTACT_EMAIL` to your real public details.
- Set `REPORTS_DIR` to private persistent storage. Confirm the host actually preserves it across restarts/deploys. Setting a path by itself does not prove durability.
- The host supplies `PORT`.

Keep API keys, `.env`, reports and signing keys out of Git and out of the APK. Set provider spending controls and appropriate access/abuse controls before broad public distribution. The local request limits are per process, not a production-wide quota.

After deployment, open the actual HTTPS URL on Android Chrome. Settings should show server build `cropsight-android-5`. Check one real photo, a tentative/unknown case, a two-view result, a follow-up and a report submission. Chrome's Install/Add to Home screen lets the user install the web app without waiting for a Play listing.

## 2. Generate the Android project

On the development Mac, in the project directory:

```sh
npm ci
npm run android:init -- --url https://YOUR-ACTUAL-HOST
```

Replace the example host. The command will reject missing or localhost origins and verify the deployed manifest/icons/server first. Bubblewrap then prompts for the application ID, signing key and SDK/JDK installation. Use the website you own. Confirm the final application ID carefully, retain the same upload key for updates, and keep its password locally in your password manager. Do not paste passwords into chat.

The generated `android/` directory and signing materials are ignored by Git. Back them up securely. No signing key has been generated by this pass.

## 3. Build the signed files

```sh
npm run android:build
```

This runs deployment/privacy/storage checks, verifies target API 36+, and invokes Bubblewrap's signed build. It expects:

- `android/app-release-signed.apk`: direct Android testing.
- `android/app-release-bundle.aab`: upload to Google Play.

No build is claimed until these files exist and the build succeeds. Test on an actual device. If the APK opens with a browser toolbar, check Digital Asset Links rather than assuming full-screen verification succeeded.

## 4. Link the website to the Android app

In Play Console, get the SHA-256 fingerprint under App integrity for the **app-signing certificate**. Google Play can use a different certificate from your local upload key. Both fingerprints may be needed for local APK and Play-installed testing.

```sh
npm run android:links -- --package YOUR.FINAL.APPLICATION.ID --fingerprint YOUR:SHA256:FINGERPRINT
```

The command generates `public/.well-known/assetlinks.json`; this is public certificate metadata, not a private key. Redeploy it on the same HTTPS origin. Then run:

```sh
npm run android:check -- --url https://YOUR-ACTUAL-HOST --package YOUR.FINAL.APPLICATION.ID
```

Verify the listed fingerprint matches the certificate actually used to sign the installed app. The preflight checks shape/configuration; device testing confirms the association.

## 5. Play Console release

Create the app with its real owner details. Upload the AAB to an internal test first. Add a store icon, feature graphic and real phone screenshots from the finished build. Use `STORE-LISTING.md` as a draft, and the live `/privacy` URL as the privacy policy.

Complete the Data safety questionnaire from actual deployment behavior. **Do not select “no data collected”:** photos leave the device for AI analysis; voluntary reports also leave the device and are retained. A provider's retention policy may prevent claiming ephemeral processing. Review provider/hosting handling of network metadata. No location, contacts or microphone permission is requested by CropSight. Report photos/comments as appropriate to Google's definitions, not as a blanket promise that nothing is shared. The policy must match the actual configured services.

Declare no ads only while the app has none. Decide intended age groups/content rating honestly; do not invent eligibility. Provide reviewer access if the deployed service is access-restricted. Rehearse on the review build with API quota available.

Complete applicable closed testing and request production access when eligible. Submit the final reviewed release; wait for Google's review. There is no Play Store link until Google accepts and publishes the listing.
